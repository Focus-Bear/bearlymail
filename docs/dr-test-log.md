# BearlyMail — DR Test Log

**Purpose**: Record all disaster recovery exercises (planned and unplanned) to demonstrate that recovery procedures have been tested and that RTO/RPO targets are achievable.

**Related**: [Disaster Recovery Runbook](./disaster-recovery-runbook.md)

---

## How to Complete an Entry

Copy the template below, fill in all fields, and append it to this file after each exercise or real incident.

```
### YYYY-MM-DD — <Scenario Name>

| Field | Value |
|---|---|
| **Date** | YYYY-MM-DD |
| **Type** | Planned exercise / Real incident |
| **Scenario** | Scenario N — <name> |
| **Environment** | Staging / Production |
| **Lead Engineer** | @github-handle |
| **Start Time** | HH:MM UTC |
| **Recovery Completed** | HH:MM UTC |
| **Actual RTO** | X min |
| **RTO Target** | X min |
| **RTO Met?** | ✅ Yes / ❌ No |
| **RPO Target** | X min / N/A |
| **RPO Met?** | ✅ Yes / ❌ No / N/A |

**Steps executed**: List any deviations from the runbook.

**Issues found**: Describe any commands that failed, steps that were missing, or documentation that was incorrect.

**Action items**:
- [ ] Issue #XX — fix runbook step Y
- [ ] Issue #XX — address gap found

**Sign-off**: @github-handle
```
