# Plan: Q&A Approved/Unapproved Separation (#1521 — Phases 2–4)

> Phase 1 (merged in this PR) removed `Q_AND_A` from compressible keys.
> Phases 2–4 implement the auto-learning → review → approval flow.

## Problem

Auto-extracted Q&A pairs from sent emails are immediately treated as approved
context. Users have no opportunity to review, correct, or reject them before
they influence auto-responder replies and suggested drafts.

## Architecture Overview

```
Sent emails → QA extraction (LLM) → saved as UNAPPROVED
                                          ↓
                              User reviews in Guide AI UI
                                    ↓              ↓
                              Approve           Reject
                            (→ AUTOGENERATED)   (→ deleted)
                                    ↓
                     Auto-responder uses approved Q&A only
```

## Phase 2 — Add `UNAPPROVED` Source Enum + Migration

**Goal:** Introduce a new source value so auto-extracted Q&A can be distinguished
from user-approved Q&A.

### Changes

#### `server/src/database/entities/user-context.entity.ts`
- Add `UNAPPROVED = "UNAPPROVED"` to the `Source` enum.

#### New migration `server/src/database/migrations/179XXXXXXXXX-AddUnapprovedSource.ts`
- `ALTER TYPE` to add `'UNAPPROVED'` to the `source` enum in PostgreSQL.
- Update existing `Q_AND_A` rows where `source = 'AUTOGENERATED'` →
  `source = 'UNAPPROVED'`. This retroactively marks all auto-extracted Q&A as
  pending review.

#### `server/src/context/context-qa-extraction.service.ts`
- In `saveQAPair()`: change `source: Source.AUTOGENERATED` →
  `source: Source.UNAPPROVED`.

### Tests
- Unit test: verify new Q&A pairs are saved with `Source.UNAPPROVED`.
- Migration test: verify existing AUTOGENERATED Q&A rows are updated.

## Phase 3 — Filter Auto-Responder to Approved Q&A Only

**Goal:** Ensure only user-reviewed Q&A influences auto-responder replies.

### Changes

#### `server/src/auto-responder/auto-responder-qa.service.ts`
- In `generateQAAnswer()`: add `source` filter to the `find()` query.
  Only load Q&A where `source IN ('AUTOGENERATED', 'USER_EDITED')` (i.e.,
  exclude `UNAPPROVED`).

```typescript
const qaContexts = await this.userContextRepository.find({
  where: {
    userId,
    contextKey: ContextKey.Q_AND_A,
    source: In([Source.AUTOGENERATED, Source.USER_EDITED]),
  },
});
```

#### `server/src/llm/llm.service.ts` / `server/src/llm/llm-misc.service.ts`
- Audit any other places that read Q&A context. If they feed into user-facing
  suggestions or auto-replies, apply the same approved-only filter.

### Tests
- Unit test: `generateQAAnswer` returns null when only UNAPPROVED Q&A exists.
- Unit test: `generateQAAnswer` works normally with AUTOGENERATED/USER_EDITED Q&A.

## Phase 4 — UI: Approved / Pending Review Tabs + Approve/Reject Actions

**Goal:** Let users review, approve, and reject auto-extracted Q&A in the
Guide AI settings.

### Backend Changes

#### `server/src/context/context.controller.ts`
- **`PATCH /context/:id/approve`** — Sets `source` from `UNAPPROVED` →
  `AUTOGENERATED`. Returns 200 with updated entity.
- **`PATCH /context/:id/reject`** — Deletes the UNAPPROVED context row.
  Returns 204.
- **`PATCH /context/approve-all-qa`** — Bulk-approve all UNAPPROVED Q&A for
  the authenticated user. Returns count of approved items.

#### `server/src/context/context.service.ts` (or equivalent)
- `approveQA(userId, contextId)` — validates ownership + UNAPPROVED source,
  updates to AUTOGENERATED.
- `rejectQA(userId, contextId)` — validates ownership + UNAPPROVED source,
  deletes row.
- `approveAllQA(userId)` — bulk update all UNAPPROVED Q&A to AUTOGENERATED.

### Frontend Changes

#### `client/src/constants/strings.ts`
- Add `CONTEXT_SOURCE_UNAPPROVED = 'UNAPPROVED'`.

#### `client/src/components/settings/guide-ai/ContextSectionsList.tsx`
- The Q&A section config gets a custom renderer (or the ContextSection
  component gains awareness of the approval workflow).

#### `client/src/components/settings/guide-ai/ContextSection.tsx`
- When `contextKey === 'Q_AND_A'`:
  - Show two sub-tabs: **Approved** (source ≠ UNAPPROVED) and
    **Pending Review** (source = UNAPPROVED) with count badges.
  - Pending Review tab shows each Q&A with:
    - ✅ Approve button → `PATCH /context/:id/approve`
    - ❌ Reject button → `PATCH /context/:id/reject`
    - ✏️ Edit button → opens inline edit (existing edit flow), then auto-approves on save.
  - "Approve All" bulk action button at the top of Pending Review tab.
  - Approved tab shows existing view (edit/delete as today).

### Tests
- API integration tests for approve/reject/approve-all endpoints.
- Frontend: component tests for tab switching, approve/reject actions.
