# Plan: Contact Groups (Issue #1623)

**Branch:** `monk/1623-contact-groups`  
**Issue:** #1623 — Let me set up contact groups  
**Author:** Monk of Modularity (AI planning agent)

---

## Problem Statement

Users have no way to define named groups of contacts (e.g., "Engineering Team", "Board Members", "All Clients"). When composing emails, they must add each recipient individually even when they repeatedly send to the same set of people. This is tedious and error-prone. The feature request is:

1. Users can **define** named contact groups in the CRM/Settings, associating a name with a list of member contacts.
2. When **composing**, typing a group name in To / CC / BCC auto-suggests the group. Selecting it expands all members into individual recipient chips.

---

## Proposed Solution

### Data model

Add a new `ContactGroup` entity and a join table `ContactGroupMember`.

**`contact-group.entity.ts`**

```
ContactGroup {
  id: uuid (PK)
  userId: string (FK → User)
  name: string (encrypted, searchable via hash index)
  nameHash: string (blind index for search)
  createdAt, updatedAt
  members: ContactGroupMember[]
}
```

**`contact-group-member.entity.ts`**

```
ContactGroupMember {
  id: uuid (PK)
  groupId: uuid (FK → ContactGroup)
  contactId: uuid (FK → Contact)
  addedAt: timestamp
}
```

Use the existing encrypted-column transformer pattern (same as `contact.entity.ts`) for `name`.

### Backend — API

New NestJS module: `server/src/contact-groups/`

**Endpoints on `ContactGroupsController`:**

| Method   | Path                        | Description                                                              |
| -------- | --------------------------- | ------------------------------------------------------------------------ |
| `GET`    | `/contact-groups`           | List all groups for the authenticated user                               |
| `POST`   | `/contact-groups`           | Create a group (`{ name, memberContactIds[] }`)                          |
| `PUT`    | `/contact-groups/:id`       | Update name and/or members                                               |
| `DELETE` | `/contact-groups/:id`       | Delete a group (does not delete underlying contacts)                     |
| `GET`    | `/contact-groups/search?q=` | Search groups by name prefix — returns group + member list for expansion |

The `/contact-groups/search` endpoint should return:

```json
[
  {
    "id": "...",
    "name": "Engineering Team",
    "memberCount": 5,
    "members": [
      { "email": "alice@co.com", "name": "Alice" },
      ...
    ]
  }
]
```

### Frontend — Settings UI

Add a **Contact Groups** section in Settings (alongside existing Contacts / CRM settings). The UI should:

- List existing groups with member count.
- Allow creation of a new group: name input + contact search/picker (reuse `FrequentContactsList` / contacts search results).
- Allow editing (rename, add/remove members).
- Allow deletion with a confirmation step.

**Files:**

- `client/src/components/settings/ContactGroupsSection.tsx` (new)
- `client/src/components/settings/ContactGroupItem.tsx` (new)
- `client/src/pages/Settings.tsx` — add ContactGroupsSection to the settings page

### Frontend — Compose: group expansion

Modify the recipient search flow to include group suggestions alongside individual contacts.

1. In `RecipientFields.tsx`, when the user types in a field, the `onSearchQueryChange` callback already triggers contact search. Extend this to also search groups via `GET /contact-groups/search?q=<query>`.
2. Display groups in the search dropdown with a distinct visual treatment (e.g., group icon + "X members" label).
3. On selection of a group, call `onAddRecipient` once per member — no server call needed at this point since `/search` already returns the member list.
4. Hook: update `useRecipientSearch` (or wherever the search logic lives in Compose) to merge contact and group results.

**Files:**

- `client/src/hooks/useRecipientSearch.ts` (new hook extracted from Compose search logic, or update existing search hook)
- `client/src/components/compose/RecipientFields.tsx` — pass group results into dropdown; handle group selection by expanding members
- `client/src/types/contactGroup.ts` (new type definitions)
- `client/src/queries/contactGroups.ts` (new React Query hooks for CRUD + search)

### Database migration

New migration file: `server/src/database/migrations/<timestamp>-create-contact-groups.ts`

Creates tables: `contact_group`, `contact_group_member`.

## Acceptance Criteria

1. **Create group:** User can navigate to Settings → Contact Groups, create a group named "Engineering Team" with 3 contacts, and it persists across page refreshes.
2. **Edit group:** User can rename a group and add/remove members.
3. **Delete group:** Deleting a group does not delete the underlying contacts.
4. **Type-to-expand in compose:** Typing "Engi" in To shows "Engineering Team (3 members)" as a suggestion.
5. **Expansion:** Selecting the group suggestion adds all 3 members as individual chips to the To field.
6. **Individual chip editing:** After expansion, individual chips can be removed without affecting the group definition.
7. **BCC expansion works:** Same expand behaviour works for BCC (not just To/CC).
8. **Empty group:** An empty group can be created and shows "(0 members)" — selecting it in compose does nothing.
9. **Group not visible to other users:** Groups are user-scoped; no cross-user leakage.
10. **No LLM involvement:** Group expansion is pure client-side data fan-out, not an AI feature.
11. **Encryption:** Group names are stored encrypted (same pattern as Contact.name).

---

## Out of Scope

- Nested groups (groups containing other groups).
- Sharing groups across users / teams (future multi-tenant feature).
- Auto-suggestion of groups based on usage patterns.
- Importing groups from Google Directory or Exchange GAL.
